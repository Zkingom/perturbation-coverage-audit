## P0-1 S1 集合与"宽度"的精确定义

**公式。** 令 μ、σ 为训练参照（`models_v04.train_reference`：μ = 训练扰动 pseudobulk 的逐基因均值，σ = 1.4826·MAD，并以 σ 的 5% 分位数为下限）。对扰动 p，s = (y_p − μ)/σ，ŝ = (ŷ_p − μ)/σ。T_k(p) 是按 |s_pg| 从大到小排序的前 k 个读出基因，排除靶基因自身所在的列（k = 50）。

S1(p) = sqrt( (1/k) Σ_{g∈T_k(p)} (s_pg − ŝ_pg)² )

**源码。** `code/models_v04.py::score_S1`（第 69 行）。靶基因列通过 `target_cols` 置为 −inf 后再排序，所以一定被排除。效应强度 `code/proxy_v06.py::e_true`（第 54 行）= 以 ŷ = μ 代入的 S1，即均值模型的 S1。**已实测核对**：开发集上 5,358 行里 `score − E_true` 的最大绝对值为 0，即均值模型的 S1 与 E_true 完全相同（不是近似相同）。

**集合与"宽度"。** 预测集是分数球 C(p) = {y : S1(p; y) ≤ t_p}，稿件报告的"宽度"是半径 t_p，而不是区间长度，单位是 σ 归一化后的量。代码中实际参与比较的是**封顶后的半径**：`methods_v06.capped_width`（第 218 行）把 +∞ 截为 2×max(校准分数)，把空集（t < 0）记为 0，再取均值。覆盖表的 `w` 列也是这个封顶值。

**审稿人关心的"S1 依赖测试响应"。** 属实且无法回避：T_k(p) 由该扰动**实测**的 s_p 选出，所以 S1 不是一个只依赖预测的分数函数，C(p) 也不是可以在实验前构造出来的集合。这一点在本工作中的定位是**审计量**：所有方法共用同一个分数，q̂ 可直接比较；它不能解释为可部署的预测区间。

**与稿件的差异（建议修改，不改数值）**：
1. Methods 要写明"宽度 = 封顶后的半径（+∞ → 2×最大校准分数，空集 → 0）"，并说明封顶规则是为处理 M3 的 +∞ 阈值而预先写入方案的。
2. 需要在 Results 首次出现 S1 时，而不只是 Methods，写明"S1 的基因集合由实测响应选出，因此 S1 是审计量而非可部署区间"。

## P0-2 宽度匹配选 α′ 时使用的全部信息

**流程。** `code/confirm_v07.py::rand_rows`（第 34 行）。对每次划分：
1. 以 M0 在 α = 0.1 下的封顶平均半径 W0 为目标；
2. 在 α 网格（0.01 到 0.40，步长 0.005，共 79 个点，`methods_v06.ALPHA_GRID`）上二分，找到相邻两点 lo、hi 使 W(lo) ≥ W0 > W(hi)；
3. 混合概率 π = (W0 − W(hi))/(W(lo) − W(hi))，使**期望**封顶平均半径恰等于 W0；
4. 每个测试单元按一个固定种子的均匀随机数 v 选用 lo 或 hi 的阈值。

**用到的信息。** `thresholds()`（第 193 行）的输入只有：校准单元的分数 `s_cal`、校准/测试/训练池折外的代理值（ĥ、d̂、ŝ、comb、E_true）、以及固定种子的均匀数。**测试单元的分数 `s_test` 不是任何一个阈值函数的参数**，只在最后一行 `covered = s_test <= t` 中用于判定覆盖。宽度目标 W0 本身也只由 `t0` 和 `s_cal` 算出。所以"用测试响应挑 α′"这一担心不成立。

**实测核验（RPE1 / GWPS，21 次划分）**：

| | M1 的 α′ 区间 | 匹配状态 | 期望宽度与 W0 的最大相对偏差 | 实际宽度/W0 |
|---|---|---|---|---|
| RPE1 | 0.060–0.115 | matched 21/21 | 1.3e−16 | 0.996–1.001 |
| GWPS | 0.085–0.110 | matched 21/21 | 1.7e−16 | 1.000–1.000 |

**覆盖保证的适用范围（必须写进稿件）。** 选定 α′ 后，该方法的理论边际保证是 **1 − α′**，不是 1 − 0.1。例如 RPE1 上 M1 的 α′ ≈ 0.06–0.115，实测边际覆盖 0.906。宽度匹配是一个**事后的公平性约束**，它把"同样的总宽度预算下谁分配得更好"作为比较对象，并不保证 1 − α。稿件现在只说"at equal mean width"，没有说明保证水平随之改变。同时，α′ 依赖 W0 与代理，严格来说破坏了校准分数的可交换性，所以匹配后的边际覆盖应作为实测量报告（已有：0.906 / 0.906），而不是宣称的保证。

## P0-3 覆盖保证针对的随机对象；GEE 的聚类单元

**随机对象。** 可交换单元是**靶基因**（TSS 组为整体分配，`code/splits_v06.py::repeated_group_kfold` 第 32 行；`data_v07.build_units` 第 115 行把 1 kb 内共享 TSS 的靶基因并入同一组，非 E 单元若与 E 单元同组则直接丢弃）。因此分裂式 conformal 的保证是：在"校准集与测试集的**基因**可交换"的假设下，对**随机抽到的一个测试基因**，P(S1 ≤ q̂) ≥ 1 − α。它不是对某个固定基因的保证，也不是对细胞的保证。整组分配使同一 TSS 组内的基因不会跨折，从而避免 CRISPRi 邻近启动子抑制造成的泄漏；代价是可交换性只在 TSS 组层面成立，组内相关性不被保证覆盖。

**GEE 的聚类。** `analysis_v06.gee_tiers`（第 59 行）与 `paired_T5`（第 81 行）都用 `groups = tss_group`，工作相关结构为独立，标准误为稳健（sandwich）。
- **同一基因跨划分的重复行是否被涵盖：是。** 每个 E 基因在 3 轮中各被测试一次，覆盖表中每个基因恰好 3 行（实测：开发集 1,786 个基因全部为 3 行，RPE1 1,751 个、GWPS 5,683 个同样全部为 3 行）。`tss_group` 是基因层面的常量，所以同一基因的 3 行必然落在同一聚类里，跨划分的重复被聚类吸收。
- 测试集中每个 TSS 组包含的基因数：RPE1 1,645 组含 1 个、53 组含 2 个；GWPS 5,216 组含 1 个、232 组含 2 个、1 组含 3 个。
- **一个稿件未说明的限制**：GEE 把 3 轮当作同一聚类内的重复观测，这在"轮与轮之间模型重新拟合、校准集不同"的意义上是近似的；它不会低估基因层面的相关，但也没有显式建模轮间的相关结构。建议在 Methods 写一句。

## P0-4 ĥ 的正值化、尺度与跨折流程

- **目标与正值化。** 学习器拟合的是 **log E_true**，预测后取 exp（`proxy_v06.fit_proxy` 第 208 行：`q = np.exp(full.predict(Xq))`）。所以 ĥ 恒为正，不需要截断，且与 E_true 同量纲（σ 归一化单位）。实测范围：开发集 1.98–8.58，RPE1 2.50–9.27，GWPS 2.82–4.90。
- **尺度。** M1 用 S1/(ĥ + c)，c = γ·median(ĥ_OOF)，确认集固定 γ = 0（开发集选出），即 c = 0，所以 M1 等价于按 ĥ 成比例地分配半径。
- **学习器。** ridge，λ 由按 TSS 组分组的内部交叉验证选出；特征为先验特征与**训练池**单元的实测响应（GO/STRING 相似度与距离、20 个最相似 GO 邻居与全部 STRING 邻居的加权平均效应强度、GO 注释数、STRING 度数）。
- **跨折。** 训练池按 TSS 组分为 5 个内部折（`proxy_v06.inner_folds` 第 135 行）。折外值 `oof` 用"去掉该折后重新拟合的学习器"预测（第 208–214 行），只用于 M1 的常数 c 和 M2 的分箱边界；查询单元（val/cal/test）的 ĥ 用全训练池拟合的学习器。邻居特征在折外版本中也只取该折以外的邻居。
- **v0.6.2 规则**：学习器只在当次划分的 E 训练单元上拟合，always-train 单元仅作为邻居和模型拟合单元。
- 与稿件一致。建议补一句"ĥ 由 log 尺度回归后取指数，因此恒正"。

## P0-7 oracle 的分母与归一化后分数的分布（**需要改稿**）

- **分母。** `methods_v06.METHODS["oracle"] = ("norm", "E")`，变量 `E` 在 `eval_v06.proxies`（第 173 行）中取自 `cache["E_calt"]`，即**实测的 E_true**（均值模型的 S1，k = 50，同一划分参照）。不是 ĥ，也不是分半估计。γ = 0，所以 oracle 的分数是 S1/E_true。
- **归一化后分数接近退化为常数。** 实测 S1/E_true 的分布：

| | 5%–95% 分位 | 变异系数 | Spearman(S1, E_true) |
|---|---|---|---|
| 开发集 | 0.813–1.043 | 0.107 | 0.941 |
| RPE1 | 0.807–1.071 | 0.097 | 0.963 |
| **GWPS** | **0.990–1.007** | **0.008** | **1.000** |

  对**均值模型**，S1 ≡ E_true，归一化分数**恒等于 1**（实测最大偏差 0.0），oracle 的覆盖完全是定义性的。对 linear-PCA，在 GWPS 上 S1/E_true 的变异系数只有 0.008，归一化分数几乎是常数，oracle 的高覆盖同样接近定义性；在 RPE1 和开发集上还有约 10% 的变异，但 S1 与 E_true 的秩相关已达 0.94–0.96。这说明 oracle 的"修复"主要反映 **S1 本身近似正比于 E_true**（因为 linear-PCA 对强扰动的预测贡献很有限），而不是"知道效应强度就能修复校准"这一可推广的结论。
- **第二个实现层面的问题：oracle 从未真正完成宽度匹配。** 实测匹配状态：RPE1 20/21 次、GWPS 21/21 次、开发集 21/21 次为 `unmatched_too_narrow`，即在 α 网格的下界 0.01 处，oracle 的封顶平均半径**仍小于** W0。实际宽度与 W0 之比：RPE1 0.668–1.001，GWPS 0.647–0.754，开发集 0.639–0.844；期望宽度与 W0 的相对偏差达 0.33–0.36。所以稿件中"width-matched oracle gain +52.0 pp / +47.0 pp"的表述不准确：oracle 是在**比 M0 更窄**的宽度下取得这些覆盖的。
- **结论与影响范围。** oracle 不进入任何确认性判定（B0、P、第 1 步、第 2 步、保护条件都不含 oracle），所以**已报告的确认性结论不受影响**；需要修改的是稿件对 oracle 的表述。按你已记录的改稿原则，oracle 只解释为"在已知实际效应尺度时的上界"，并明确：(i) 对均值模型它是定义性的，对 linear-PCA 在 GWPS 上近乎定义性；(ii) 它的宽度并未匹配到 M0，而是更窄（给出比值区间）。同时删除"修复需要且只需要预测效应强度""bounds any repair"等表述。
