# 审计 B 聚类设计扫描（v0.4.2，只用先验，等待用户确认）

日期：2026-10-03。本次没有读取任何表达数据，也没有计算任何覆盖率。

## 结论

1. **按你的标准（最大簇 ≤ E 的 5%，且能由整簇凑出约 15% 的测试集），推荐原始 GO Jaccard 图、分辨率 8，并把测试集的停止规则改为规则 C。** 这个配置下：
   - 70 个簇，最大簇 68 个单元（占 E 的 3.8%）；
   - 规则 C 下 97.5% 的抽样落在 13.5%–16.5%；
   - 5 个 Leiden 种子之间的 ARI 平均为 0.82。
2. **在现有停止规则（规则 G）下，任何一个合理的分辨率都达不到“约 15%”。** 原因是规则 G 一直加簇，直到测试集 ≥ 15% 才停，并且要补齐被切开的 TSS 组，所以测试集比例总是偏大。分辨率 5 时中位数是 17.2%，只有 21% 的抽样落在 13.5%–16.5%。所以停止规则也需要你确认。
3. **审计 B 造成的分布偏移比预想的小。** 推荐配置下，测试单元 D_GO（到训练池）的中位数只比审计 A 高 0.038：审计 A 是 0.770，审计 B 是 0.807。作为参照，E 的 D_GO 四分位距约为 0.66–0.81。可能的原因有两个：
   - 257 个始终训练的扰动不参与聚类，其中可能有与测试簇功能相近的基因；
   - D_GO 是对前 20 个邻居的 Jaccard 取平均，宽泛的 GO 项使远近之间的差别不大。

   这意味着审计 B 能检验“功能上更陌生”的场景，但陌生的程度有限。如果审计 B 的覆盖与审计 A 相近，不能据此得出“结构化 OOD 不影响覆盖”的结论。我建议在报告中同时写明这个偏移量。

## 方法（现在暂定，确认后写入方案）

- **节点**：E 的 1,786 个单元。始终训练的扰动不参与聚类，划分时总是放在训练集中。
- **图**：对每个基因，取 GO Jaccard 最大的 20 个邻居，只保留 J > 0 的边；对称化时取较大值，边权就是 Jaccard。邻居数 20 与 D_GO 的 top-20、GEARS 的 `num_similar_genes_go_graph = 20` 一致。
  - 原始图用全部 GO 项，有 28,160 条边，没有孤立点。
  - 过滤图删除注释超过 500 个基因的 GO 项（共 29 项），有 24,318 条边，24 个孤立基因（过滤后不剩任何 GO 项）。孤立基因各自成为单点簇。
- **Leiden**：`leidenalg.RBConfigurationVertexPartition`（加权，带分辨率参数），种子 20261001。扫描的分辨率为 0.5、1、2、3、5、8、12、20、30。
- **测试集停止规则**：
  - **规则 G**（现行，`code/splits_v04.py`）：按随机顺序逐个加入整簇，直到测试集 ≥ 15%·n，再补齐被切开的 TSS 组。
  - **规则 C**（备选）：按随机顺序考察每个整簇，连同它牵涉的 TSS 组一起；只有当加入后测试集大小离 15%·n 更近（或一样近）时才加入；达到 15% 后停止。它的代价是：比较大的簇被跳过的概率稍高，因此测试集略偏向较小的簇。
  - 两种规则下，余下的单元都按 TSS 组随机分配：验证集占 10%·n，校准集占 15%·n，其余进训练集。
- **可行率**：200 次划分（种子 20261001+0 至 +199）中，测试集比例落在 13.5%–16.5% 的比例。
- **D_GO 偏移**：用 50 次划分计算测试单元 D_GO 的中位数（到训练池：E 的训练集 + 257 个始终训练扰动），再取 50 次的中位数。审计 A 的对照值用同样的 50 个种子计算。

## 推荐理由与备选

- **推荐：原始图、分辨率 8、规则 C。**
  - 选原始图，是因为它与主距离 D_GO 用的是同一个 Jaccard，也与 GEARS 的 GO 图同源。
  - 分辨率 8 是在满足“最大簇 ≤ 5%（所有种子都满足）”且“规则 C 可行率 ≥ 95%”的前提下最小的分辨率。分辨率越小，簇越大，测试集在功能上越陌生，偏移也越大。
- **备选 1：原始图、分辨率 5、规则 C。** 偏移稍大（+0.040），但最大簇处在 5% 边界上（种子 0 时为 89/1,786 = 4.98%），规则 C 的可行率为 90%。
- **备选 2：过滤图、分辨率 8、规则 C。** 可行率 99.5%，偏移 +0.036。它与 D_GO_filt 敏感性分析使用的是同一套过滤规则。
- **规则 G 下的可行配置**：要满足可行率条件，分辨率需要 ≥ 20。那时簇的中位大小 ≤ 7，单点簇有 34 个以上，审计 B 已接近随机划分，不建议采用。

## 需要你确认

1. 用哪张图、哪个分辨率。
2. 停止规则用 G 还是 C。若选 C，需要把它写入 `splits_v04.py`，并在方案中记录。
3. “约 15%”的容许范围是否就是 13.5%–16.5%，可行率门槛是否为 95%。这两个数是我为了操作化你的标准而暂定的。
