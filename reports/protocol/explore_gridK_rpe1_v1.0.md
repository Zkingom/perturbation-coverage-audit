# 探索性分析方案 v1.0：扩大 K / d 网格（RPE1，确认之后；2026-10-15 经用户批准，运行前冻结）

日期：2026-10-12。本分析属于**确认之后的探索性分析**，不改变也不覆盖 v0.7 的任何确认性结论。

## 动机

RPE1 确认运行的 21 次划分里，linear-PCA 的 K 全部选在 50，linear-GO 的 d 全部选在 100，都碰到了网格上界。开发集上 K 有 16/21 次、d 有 21/21 次碰到上界。所以需要检验：在调参更充分的线性模型下，T5 失效和 M1 的修复是否依然存在。

## 设计

1. **数据与划分**：只用 RPE1，沿用 C0 已写好的 21 个只读划分（`splits/v0.7_conf/rpe1`），不新建划分。
2. **网格**（用户指定）：
   - linear-PCA：K ∈ {50, 100, 200}；
   - linear-GO：d ∈ {100, 200}。
   
   仍在每次划分的验证集上，按 v0.5 的规则选取，其余设置都不变。
3. **方法与超参数**：全部沿用 FROZEN（M1 γ = 0、Mdist-M B = 3 等），**不重新选方法，也不重新选超参数**。ĥ、d̂、ŝ 的学习器按原规则重新训练，因为模型预测会作为特征输入。
4. **重算环节**：stage1 → ext → stage2 → finish，用可续跑模式（`resume_v07`）。输出写到单独的目录 `results/explore_v0.7/rpe1_gridK/`，不碰确认结果目录。
5. **实现方式**：K 和 d 的候选网格要以参数形式传入，不改冻结常量。具体做法是新增一个探索入口，在运行时覆盖候选网格并写入日志。上线前要先做两项检查：
   - 用原网格运行时，结果与已有确认缓存逐字节一致；
   - 在合成数据上跑通扩展网格。
6. **报告的终点**（描述性，不做假设检验结论）：
   - M0 和 M1 在 T5 的覆盖率；
   - E1、E2（E2 必须同时给出子集宽度比）；
   - 第 2 步的差值；
   - 各次划分选中的 K 和 d 的分布，以及是否仍然碰到新网格的上界；
   - 验证集上 S1 误差的变化。
7. **解读规则**（预先写定）：
   - 若扩展网格后 M0 的 T5 覆盖仍 < 0.85、M1 仍高于 M0，则写作"失效与部分修复在更充分调参下仍存在"；
   - 若失效明显减弱，则如实报告，并在论文中注明主结论依赖于模型的调参程度；
   - 若 K = 200 仍碰到上界，照实报告，不再继续扩大网格。

## 资源估计（未实测）

- linear-PCA 的拟合代价大致随 K 线性增长，stage1 单次划分预计约 3–5 分钟（原来约 2 分钟）。
- 全流程预计 2–3 小时，可以分几天在断电窗口之间完成。
- 必须在 GWPS 确认完成之后，或者在不和 GWPS 争用内存的时段运行。


## v1.0 实现细节（2026-10-15 运行前写入）

1. **网格的含义**：草案中的"K ∈ {50, 100, 200}、d ∈ {100, 200}"解释为在原网格上**扩展**，即
   - K ∈ {5, 10, 20, 30, 50, 100, 200}；
   - d ∈ {2, 5, 10, 20, 30, 50, 100, 200}。

   这样做的理由是，选择规则不变（在验证集上选误差最小者），并且原网格中的每个候选都保留，扩展后的网格是原网格的超集。如果只取 {50, 100, 200}，等于同时删掉了原网格中较小的候选，这样就无法区分"扩大网格"和"缩小网格"各自的影响。
2. **d = 200 的 GO 嵌入**：对同一个 GO 矩阵用 eigsh 求 k = 200 的嵌入（`explore_gridK_v07.py prep`），写入 `data/processed/priors_explore/go_ase200_hybrid.npz`。
   - 第 1–100 列直接沿用 go_ase100.npz 的原值，所以 d ≤ 100 的模型与确认运行完全相同；第 101–200 列取自 k = 200 的解。
   - 嵌套性检查：k = 200 解的前 100 列在对齐符号后，与 go_ase100 的最大绝对差为 9.6e−14，特征值的最大差为 5.3e−13。
3. **运行方式**：通过 `code/explore_gridK_v07.py` 在运行时覆盖候选网格、嵌入矩阵和输出目录，冻结的代码文件不做修改。流程沿用已验证的可续跑模式（低内存加载器，finish 用 F2c）。输出写入 `results/explore_v0.7/rpe1_gridK/`。
4. **上线前检查**：用原网格在第 0 次划分上运行，输出写到单独目录；要求 stage1 缓存与确认缓存 `results/conf_v0.7/rpe1/cache/split_00.pkl` **逐字节一致**，ext 数组逐位一致。
   - 偏离草案之处：草案原计划"在合成数据上跑通扩展网格"，这里不做。原因是合成数据检验不了 K = 200 在真实维度下是否可行；可行性改由真实运行中的断言和日志来确认。
5. 其余设置（终点、解读规则、上界规则）沿用草案，不变。
