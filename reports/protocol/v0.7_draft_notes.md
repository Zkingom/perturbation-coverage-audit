# v0.7 草案：已确定纳入的内容（用户 2026-10-06/07 确认 D0′ 结果时决定）

本文件只记录决定，不是方案正文。v0.7 草案将在 D1 结果出来后起草，冻结前必须经用户审阅确认。

1. **宽度匹配**：改为在相邻两个 α′ 之间做随机化插值，使平均宽度与 M0 精确相等。具体做法是：对每个测试单元，以概率 π 使用较小 α′ 的阈值，否则使用较大 α′ 的阈值；π 由宽度方程解出。随机数用固定种子。如果 oracle 在网格端点 α′ = 0.01 时仍然比 M0 窄，就无法匹配，此时照实报告宽度比。
2. **W 判据 (c)**（边际覆盖在 [0.88, 0.92]）改在名义 α 下判定；宽度匹配下的边际覆盖只作描述性报告。(a)(b)(d) 仍在宽度匹配下判定。
3. **混杂回归**：主报告用系数符号加基因层面 cluster bootstrap 的 95% CI；Firth 惩罚 logistic 作为敏感性分析。OR 的点估计在近似分离时不作解读。
4. **oracle 的 γ** 按规则 7.2 选择（宽度匹配后 T5 覆盖最高；相差在容差内时取更简单的值）。
5. **Mcomb**：σ̂_comb = exp(OLS：log 折外分数 ~ log ĥ + log d̂)，系数在训练池上拟合；常数 c = γ × 训练池拟合值（样本内）的中位数。
6. **M_dist 的竞争力**（第 1 项决定）：D1 中报告 Mdist-N 和 Mdist-M 相对 M0 在 D_GO 和 D_STRING 分层上的覆盖改进。如果开发集上几乎没有改进，在 v0.7 之前提出更强的类 PRESCRIBE 变体，由用户决定。
7. **D0′ dist 场景**：1 项预期未通过，如实记录，诊断注明为事后分析，不重跑。
